# Command: Review PR

When asked to review changes, use this process.

## Review priorities
1. correctness
2. regression risk
3. readability
4. maintainability
5. test coverage
6. security/data handling

## Output format
- summary
- blocking issues
- non-blocking suggestions
- test coverage notes
- overall verdict

## Severity levels
- High: likely bug, security issue, or major regression risk
- Medium: maintainability/readability issue with real impact
- Low: polish or consistency improvement

## Expectations
- be specific
- point to exact concerns
- suggest practical fixes
- avoid nitpicks unless they matter
