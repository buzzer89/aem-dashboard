# Styling Rules

## General
- Follow the repo's current styling approach
- Prefer consistency over novelty
- Avoid unnecessary visual changes in functional tasks

## Tailwind usage
- Reuse existing utility patterns
- Prefer readable class groupings
- Avoid overly long class strings when extraction improves clarity

## UI consistency
- Respect spacing, typography, border radius, and color patterns already present
- Reuse design tokens or shared classes if available
- Do not introduce a new visual pattern without reason

## Scope control
- Only adjust styles related to the task
- Do not do drive-by cosmetic changes
